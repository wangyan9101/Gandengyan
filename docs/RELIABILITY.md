# 阶段4.4可靠性测试与交付报告

日期：2026-10-23。工程：E:\Dev\Cocos\Gandengyan，Creator 3.8.5。仅本地可靠性开发及云迁移设计；没有云连接、部署、新Cocos工程或玩法变更。

## 1. 实现与已确认策略

- 服务端为逻辑玩家生成32字节安全随机恢复凭证，单独发送给本人；凭证不进入公开房间、其他人的快照、URL或日志。客户端仅在当前NetworkClient内存保存，按服务器地址隔离。
- 断线保留身份、席位、GameState、请求回执和结算账本，取消准备。恢复凭证校验后撤销旧连接，发回最新公共状态及本人的手牌，不重新发牌。旧连接的命令/关闭事件不能影响新连接。
- 全员离线后保留30分钟，全部成员离线时间均超过窗口才回收，不产生胜负或补结算。仍有在线成员时不删除进行中房间。
- 非主动网络中断自动退避重试，250ms开始、每次翻倍至8s，最多10次；连接握手5s超时。手动断开取消重试，凭证过期/身份被替换停止重试；可在原客户端手动重连。
- 请求5s无确认视作结果未知，恢复服务端快照；不自动用新requestId补发旧出牌。相同身份跨连接保留同ID/载荷回执，不同载荷拒绝。牌局stateVersion与房间version分别校验。
- 用户已确认：大厅主动退出释放席位，房主由最早入座的在线成员接任；没有在线成员时保留最早剩余成员为房主，仍不能开局。加入时分配空席，不与原席位碰撞。
- 对局及已结算房间主动退出保留席位、手牌/结算和房主，便于本人恢复与赢家续庄；不允许新访客顶替。轮到离线者等待恢复，其余在线玩家可以完成自己的合法回合。
- 操作超时默认60s，服务器约1s维护粒度，每个匹配轮次/版本只提示一次；不自动过牌、托管、判负或结算。时钟留在应用层，规则引擎仍无时间/IO依赖。

## 2. BUG修复

| 问题 | 修复与回归依据 |
| --- | --- |
| 每次连接创建新身份，无法取回原手牌 | 凭证映射稳定身份，恢复最新本人投影；2～8人、单双副全部验证 |
| 全员离线立即删除原房间 | 全员离线保留窗口与有界清理；虚拟时钟覆盖过期边界，不伪造结算 |
| 断线清除去重回执，无法确认已提交操作 | 回执跟随逻辑身份，模拟提交成功/回执丢失，恢复后只出现一次状态推进 |
| 旧socket仍可能发动作或关闭新身份 | 连接ID映射撤销，旧命令忽略、旧close不把新连接标为离线 |
| 大厅退出后空位分配可能与保留席重复 | 取第一个空座、按席位排序，在线接任房主；真实网络退出/补位回归 |
| 已退出者可能重读旧请求的缓存快照 | 返回旧Sync回执前再次检查当前房间归属，离开后拒绝旧房间数据 |
| 发送异常可中断广播和请求完成 | 状态/回执先提交，隔离单个发送失败，其他成员仍收到同次状态 |
| 网络恢复没有统一UI重建和错误清理 | 清理旧RemoteSession，权威快照重建本人牌桌并清除旧连接错误；原AI路径保留 |
| 同步抛错的socket工厂可能让重试预算重置 | 重试使用独立open流程，失败不清零预算，最多10次并可取消 |
| 进行中牌桌没有返回大厅入口，无法找到退出按钮 | 补上牌桌右上“返回房间”和大厅“返回牌桌”；访问大厅保持连接，同一会话可继续对局；新增实际控制器回归 |

## 5. 风险与尚未验证

1. **仅内存恢复**：刷新/关闭页面、销毁NetworkClient或服务进程重启会丢失恢复能力。没有微信认证、持久化或跨设备账号恢复；单实例内存服务不支持多进程共同权威写入。
2. **保守等待可能长期停局**：有在线成员时离线席位不自动移除，超时不代打/判负；已完成房间退出也不释放席位。解散、踢人和长期归档需要进一步决策。
3. **剩王规则未决**：仍保留awaiting-rule，不判胜、不结算，不能承诺所有牌序/策略都有正常终局。
4. **会话限额**：每个逻辑身份最多1024个不同请求，重连不重置；128同时连接、100房间、2048个保留身份，超限拒绝。长时间多局及极限压力未实测；后续需持久化回执压缩/墓碑，不能简单清空去重绕过限额。
5. **访客安全边界**：本地ws无TLS，凭证是持有者凭证，只适用于可信本机/局域网测试，不作为公网账号服务。后续云身份、TLS及受控服务认证需单独实现。
6. **端上未验证**：本轮未打开Creator人工预览，未做多浏览器UI操作、跨设备、后台挂起、微信构建、真机和长时间弱网/压力测试。客户端严格类型和VM测试通过不等同端上通过。
7. **恢复次数有限**：10次失败后停止，保留原窗口可手动点连接重试。过期/替换身份不无限重连。超时提示为即时通知，离线期间错过不补发历史提示，恢复牌局状态仍以快照为准。

```powershell
Set-Location 'E:\Dev\Cocos\Gandengyan'
npm run client:sync
npm run check:all
npm run check:network
```

1. Creator 3.8.5打开现有工程，等待导入及新.meta生成；打开assets/scene.scene并浏览器预览，用**实际完整预览URL**开A/B两个窗口，不创建新工程。
2. 两窗口进入本地联机并连接ws://127.0.0.1:8787/rooms；A建2人房、B入房，分别准备，A开始。记录本人手牌、当前玩家、余牌数及房号。
3. **主动退出恢复**：A点牌桌右上“返回房间”，再点大厅左下“退出房间”，B应看到A离线且牌局未重置；A在原窗口点“连接服务器”，应自动恢复原房/本人手牌并回到牌桌，不需重新入房。只想查看大厅时，可点“返回牌桌”继续，不会退出或重新发牌。不得在恢复测试中刷新窗口。
4. **意外断线**：在A浏览器开发者工具Network选择Offline，确认WS确实断开（浏览器对已有WS的离线模拟行为可能不同，服务端心跳检测最长约30s）。B应看到离线；A改回Online，在重试窗口内自动恢复。若重试已耗尽，在原窗口手动点连接。若工具未切断WS，则该手动步骤未有效模拟断网，不能报告通过。
5. A断线时B完成自己的合法回合；轮到A则等待，不自动过牌。A恢复后继续原局。双方等60s不操作，只出现超时提示，手牌、回合、倍率和积分不变；行动后继续。
6. **大厅房主退出**：用新建的等待房验证A建房/B加入后A点退出，B接任房主；A重连后可重新加入空位。不要把进行中退出当作释放席位。
7. 完成一局、核对相同结算，重新准备并由房主开始下一局，确认上一局赢家任庄。扩展至6/8窗口；2～8人自动恢复回归可运行：

```powershell
npx vitest run --config vitest.network.config.mts tests/network/reliability.test.ts
```

8. 单机入口验证真人选牌/提示/出牌、AI接牌、结算与重开；断开服务器时单机也应继续可玩。不要为了测试恢复而重启服务器；服务器重启丢失内存是已知边界。
