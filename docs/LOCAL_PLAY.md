# 本地可玩版：启动与验收

日期：2026-10-20。目标编辑器为 Creator **3.8.5**。本阶段只有本地进程内对局，不连接微信、腾讯云或其他网络服务。

## 1. 准备与生成代码

```powershell
npm ci
npm run client:sync
npm run check
```

若 npm 默认缓存无写权限，使用 `npm ci --cache "$env:TEMP/gandengyan-npm-cache"`。

`client:sync` 将 `packages/rules/src/` 和 `packages/local/src/` 同步至 `assets/scripts/generated/`，只改写本地模块的导入路径，绝不修改 `.meta`。这些文件含 GENERATED 标记，不能手动修改；源代码只有一份。`client:verify` 逐文件比对，防止客户端规则漂移。以后修改 local 源码后先运行同步，再切回编辑器。

## 2. 打开已有场景（新建挂载仅作历史参考）

2026-10-23 更新：项目已有 `assets/scene.scene`，包含 Canvas、UI Camera 和 LocalGameApp，用户已确认 Creator 运行成功。当前直接打开此场景预览，不要重复建场景或挂载组件。以下步骤仅供理解最初的场景创建过程。

1. 在 Creator Dashboard 中用 **3.8.5** 打开当前目录，等待脚本和资源导入。新 `.meta` 由编辑器生成；保留生成后的文件，不删除重建。
2. 在 Assets 创建一个**新场景**，保存为 `assets/scenes/local-game.scene`。已有其他场景时不要覆盖它们。
3. 在场景中创建 **Canvas 和配套 UI Camera**（用编辑器创建 Canvas 的菜单即可自动配套）；若场景模板已有 Canvas/UI Camera，则复用，避免重复相机。
4. 选中 Canvas，将 `assets/scripts/presentation/local-game-app.ts` 拖到 Inspector，确认出现 **LocalGameApp** 组件。只挂一次。
5. 保存场景。无需拖拽任何 Button、Label、手牌节点或预制体，也无需绑定点击事件。界面由组件运行时创建，复用卡牌、座位和结算行节点。
6. 点击编辑器顶部的浏览器预览按钮，预览**当前场景**。应显示“创建游戏”主界面；若显示空白，确认当前打开的是刚保存的场景、Canvas 绑定了 UI Camera，Console 没有脚本错误。

上述一次性场景创建与挂载已完成，场景和 `.meta` 随阶段3基线保存；继续保留现有 UUID 与资源引用。

## 3. 参数和玩法

- 人数使用加减按钮选 2～8 人；其中只有你是真人，其余为电脑。
- 选择 1/2 副牌，即 54/108 张；损失封顶使用加减按钮选 5～50 整数。
- 你固定坐第一席并任庄家，初始 6 张；其他人各 5 张。
- 点击手牌选择，再点取消；选中的牌升起并变为金色。牌较多时在手牌区域左右滑动，拖动不会当作普通点击处理。
- “提示”只帮你选出一个合法动作，不会自动提交；点“出牌”才执行。没有合法接牌时提示会清空选择，此时可过牌。
- 包含王的同一批牌可能有不同解释，用“牌型解释”按钮切换；上方显示当前解释，出牌时提交相同声明，由引擎再次校验。
- “过牌”只有你接牌时可用，自由领出时禁用；非你的回合禁止提交动作。
- 顶部显示电脑余牌数、公共牌堆数量、B 与 2^B、封顶；中央显示当前行动者和最近一次公开出牌。每轮结束补牌后，仍可查看上一手牌型。
- 电脑约每 0.55 秒执行一步；提示规划和电脑使用同一候选生成器，每个动作都由原规则引擎校验，不能改写手牌或倍率。
- 结算页显示每人剩余实体手牌数、全局倍数、积分变化和是否触及损失封顶。赢家收取输家实际扣分总和，收入不封顶。
- “相同配置再开一局”新建本地会话，所有版本、B、选牌、牌堆和结算重置。AI 由组件 update 驱动，没有遗留异步回调在重开后继续出牌。
- 牌桌上的“主界面”会放弃当前本地局且不记分；这只是本地练习操作，不是未来联机退出规则。

## 4. 一整局的可复现验收

1. 在 Canvas 的 LocalGameApp 组件把 **Test Seed 设为 2026**，AI Delay 保持 0.55（也可设 0.15 加快验收）。
2. 浏览器预览，选择默认 **3 人、1 副、封顶 20**，创建游戏。
3. 每次轮到你，点击“提示”；有选牌就“出牌”，无合法接牌就“过牌”。等待电脑自动行动。
4. 应进入真正的结算页，某位玩家剩 0 张。核对每个输家的损失不超过 20，所有增减相加为 0。
5. 点“相同配置再开一局”，核对 B=0、倍率=1、庄家 6 张、其余 5 张，无上局结算/选牌残留。
6. 返回主界面，重复人数 2/8、牌副数 1/2、封顶 5/50。自动化已使用种子 2026 覆盖 2～8 人 × 1/2 副全部 14 种配置到真正结算。
7. 验收结束把 Test Seed 设回 **0**。0 使用本地 Math.random；固定非零种子每次重开得到相同牌序，仅用于调试。在线服务不得使用此随机源。

该流程的“完整一局”已经在本地会话集成测试中执行；编辑器预览、Web 构建和手机触摸布局仍须按本页进行端上验收，不能把 Node 测试等同于端上通过。

## 5. 横屏与布局验收

使用 1280×720 设计尺寸和 SHOW_ALL 策略，按比例保留整个界面；宽屏/平板可能有留边，不裁掉按钮。Canvas 随窗口调整，内容区保持设计尺寸。请在浏览器设备模拟/构建后核对：1280×720、1334×750、1920×1080、2400×1080、1024×768。竖屏请旋转设备，当前不提供竖屏重排。

本地 Web 构建时，在 Build 面板选择 Web Mobile 或 Web Desktop，将新场景加入 Included Scenes 并设为 Start Scene；Web Mobile 的方向选择横屏。无需填写微信 AppID 或云环境。构建参数由编辑器保存，不在本次代码中覆盖现有工程设置。

## 6. 已知规则限制

用户尚未决定“仅剩王且轮到自由领出”的后续处理。若引擎进入 `awaiting-rule`，界面显示**暂停、不判胜、不扣分**，可返回或重新开局。不会把这类局伪装成正常结算；本阶段没有修改已通过测试的规则来强行结束它。

AI 会尽量用普通牌搭出王，减少搁置王的情况，但不能保证任意真人策略/随机牌序都避开未决分支。要使所有可能的对局均有定义终局，需要先确定该规则；已有正常对局不受影响。

## 7. 检查命令与职责

```powershell
npm run check             # 规则与 local 严格检查、全部测试、生成镜像一致性
npm run typecheck:client  # Creator 导入后，使用 temp 中真实 cc 声明检查 UI
npm run check:all         # 提交前统一验证以上两项，需先完成 Creator 导入
```

`typecheck:client` 需要本机 Creator 生成的 temp 声明；仅跳过引擎第三方 .d.ts 内部检查，项目脚本保持 strict，不伪造 cc 类型。不新增运行时依赖。

界面仅从 LocalSession.snapshot 获取本人和公开投影。全量状态留在进程内会话，电脑规划只使用自身手牌和公开信息。此本地隔离不是联机认证或反作弊，未来联网仍由服务端唯一裁决。

编辑器操作参考：[Creator 3.8 创建场景](https://docs.cocos.com/creator/3.8/manual/en/getting-started/helloworld/index.html)、[将脚本挂载到节点](https://docs.cocos.com/creator/3.8/manual/en/scripting/setup.html)。

## 8. 微信构建更新与出牌按钮排查（2026-10-21）

本次检查实际微信产物发现：Creator 的数组假设式展开转换将 `[...selectedSet]` 编译成 `[].concat(selectedSet)`，得到包含 Set 对象的数组，而不是 cardId 字符串数组，导致选牌无法识别、出牌按钮不启用。UI 中所有选牌集合转数组已改为 `Array.from`；保留规则引擎和命令校验，另补充模拟该编译模式的回归测试。该测试不是微信端触摸或渲染测试。

源码修复后需按以下顺序更新到模拟器/手机：

1. 若修改过 packages 源码先执行 `npm run client:sync`；本次修复仅改 UI，现有镜像无需额外修改。
2. 切回 Creator 等待脚本编译完成，在 Build 面板选微信小游戏，重新点击**构建**，确认无错误；不要仅在微信工具点编译，也不要只复制 game.js。
3. 微信开发者工具打开 Creator 最新输出的 `build/wechatgame` 目录，然后重新编译。若仍像旧包，清除编译缓存再编译，并确认导入目录正确。
4. 重新点**预览**生成新二维码，iPhone 退出旧小游戏后扫描新码；若用真机调试，则重新启动调试会话。重新创建牌局，选一张普通牌或点击提示，合法时出牌按钮应亮起。

新包可在 `assets/main/index.js` 中核对选牌转换使用 `Array.from(...selected...)`，而不是 `[].concat(...selected...)`。只有合法选牌且轮到真人时才启用出牌；单独选择王或不合法组合仍禁用，这是已有规则。
