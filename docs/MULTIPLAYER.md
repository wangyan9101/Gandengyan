# 本地多人实时对局（阶段4.4更新）

日期：2026-10-23。沿用Cocos Creator 3.8.5现有工程与assets/scene.scene。阶段4.3已实现发牌与整局；阶段4.4新增身份/牌局恢复、自动重连与退出/超时策略，保留单机真人＋AI。最新测试和断线验收见 [RELIABILITY.md](RELIABILITY.md)，云迁移仅设计见 [CLOUDBASE_MIGRATION.md](CLOUDBASE_MIGRATION.md)。

## 1. 本阶段行为

- 2～8个独立连接加入同一房间；满员、全部在线且准备后，仅房主可开始。
- 服务端通过node:crypto安全随机源调用原createGame；54/108张实体牌与cardId复用原模型，无第二套规则。
- 首局房主（第一席）任庄，庄家6张、其他人5张。用户已确认：**下一局由上一局赢家任庄**；房主身份不因此转让。
- 客户端通过play/pass提交意图；服务端从当前连接绑定playerId，调用原applyCommand判断回合、归属、牌型、过牌、补牌、计倍和胜负。非法动作不改变权威状态。
- 每次合法动作后，逐连接发送公开状态＋本人的手牌；不广播GameState，不广播所有私有投影的集合，不把隐藏牌序放入公共响应或日志。
- 结算由规则引擎在服务端计算，输家损失min(剩余实体牌数×2^B, cap)，cap为5～50整数；赢家收取实际损失，收入不封顶。包含制胜炸弹。
- 单局结束后清除所有准备标记；每人重新准备，由原房主开始下一局，生成新roundId，版本/B/桌面/结算重置，按上局赢家席位发6张并先领出。
- 仍是临时访客身份与本地内存状态；现在支持同一客户端凭证恢复和掉线重连，全员离线后保留30分钟。无微信账号、云服务、数据库或支付；刷新窗口、销毁客户端或重启服务器不能恢复。

## 3. 完整两人操作步骤

1. A、B都进入“本地联机模式”，连接ws://127.0.0.1:8787/rooms，等待“已连接”。
2. A选择2人、1副或2副牌、损失封顶5～50及适用炸弹张数，创建房间；B输入A的六位房号加入。
3. 核对双方看到相同房号、成员和配置；分别点击准备。若发生版本冲突，客户端同步后提示重试，重新点击即可，不会覆盖另一人的状态。
4. A点击“房主开始”，两个窗口自动进入牌桌。A初始6张并先出，B初始5张；每个窗口只能看到自己的牌，其他玩家只显示余牌数。
5. 轮到谁，谁在自己的窗口点击牌面选牌、切换牌型解释后“出牌”，或用“提示”选牌再手动点“出牌”。有桌面牌时可“过牌”；自由领出时不能过牌。联机不会自动替真人行动。
6. 每次操作等待服务端确认；比较两个窗口的当前玩家、公开出牌、各人余牌数、隐藏牌堆数量及倍率。对手未公开的持牌和隐藏牌序不得出现。
7. 按轮操作到某人出完。轮结束与补牌由服务端原引擎执行，不在客户端补牌。
8. 所有窗口应出现相同单局结算。核对输家扣分不超过cap、增减总和为0、B与倍率一致；赢家可超过cap。不要把“所有人净变化都受cap限制”作为期望。
9. 每个窗口点击“回房准备下一局”（或返回房间）。各自再次准备，由原房主点击“房主开始下一局”。
10. 所有窗口自动进入新局。核对上局赢家取得6张并先出，其他人5张；新roundId、版本0、B=0、倍率1、无上局选牌和结算残留。
11. 继续操作第二局到结算，验证同房持续对局。不要刷新浏览器来续局；同一窗口临时断开可重新连接恢复，正常续局只需回房准备。
12. 单机回归：从主界面进入“单机：真人＋AI”，验证提示、出牌、AI、结算与重开；单机不依赖服务端。

## 4. 六人/八人及双副牌

用同样预览URL打开6或8个独立窗口；房主创建对应容量，各窗口分别连接、加入、准备。所有人准备后才允许开始。各玩家必须在自己的窗口操作，无法代替其他连接出牌。分别执行1副、2副与封顶5/50的测试。

六人建议验证两整局：第一局完成后，原房主仍负责开始，**上一局赢家**负责新局首手；这两个角色可能是不同玩家。

## 5. 局域网其他设备（可选，需手动环境配置）

默认127.0.0.1只允许同机访问。若要其他设备连接，先确保Creator预览或Web构建可被局域网访问，并记录其实际Origin（协议＋主机＋端口）。在Windows服务端设置：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '8787'
# 以下IP和端口只是示例，必须改成实际提供Cocos网页的Origin，不含末尾斜杠。
$env:ALLOWED_ORIGINS = 'http://192.168.1.20:7456'
npm run server:dev
```

其他设备的服务器地址应填ws://服务器实际局域网IP:8787/rooms，不能填其自身127.0.0.1。多个网页Origin以逗号分隔，精确匹配，不支持通配。由用户手动核对Windows防火墙、网络连通性及浏览器HTTP/HTTPS混合内容限制，不自动修改安全设置。这仍是本地访客测试服务，不能据此作为公网生产服务；本轮未做跨设备或微信网络验收。

## 6. 协议、安全和一致性

- public.version为牌局stateVersion；room.version是房间版本。play/pass的expectedVersion对比前者；ready/start对比后者，不能混用。
- create/join首局roundId=null；ready/start在首局前为null，在已结束局重新准备/开始时必须携带当前roundId。旧局play/pass返回wrong-round；未结束不能重新开始。
- 所有消息仍有protocolVersion、requestId、roomId、roundId、expectedVersion，且接受unknown的运行时白名单验证。客户端不能提交playerId、手牌快照、赢家或积分。
- 单进程同步串行裁决，没有读后异步覆盖。先提交新状态和单局账本，再保存请求回执，之后发送响应/广播。未来多进程或数据库需另做事务方案。
- 相同恢复身份的同requestId同载荷返回原结果，跨连接仍去重；不同载荷返回request-conflict。跨局上下文在请求体中校验；旧回执不会让客户端倒退房间/局版本。
- 按roundId记录单局结算；已结束拒绝新出牌/过牌。重复制胜动作不重复记分或计倍。账本、回执、牌局均只在当前服务进程内存，重启即丢失，不声称已提供持久化审计。
- RemoteSession不乐观改牌；广播与请求响应交错时确认结果而不回滚快照。stale-version后只同步本人快照，**不自动重发旧动作**。LobbyClient在新roundId替换旧RemoteSession，清理选择和旧回调；准备等房间变化可在牌局版本不变时更新。
- 当前每个逻辑会话最多1024个不同请求ID，重连不重置；默认每10秒60条消息、最大65536字节、128连接/100房、2048个保留会话。自动化快速整局使用可信测试配置放宽速率及复现随机源；CLI没有客户端可选种子或调高限额入口。

## 7. 未决规则与限制

- 仅剩王并需自由领出时，仍先按既有规则补牌；无法领出则awaiting-rule。全员显示暂停、不判胜、不扣分，不允许把暂停局作为已结束局续局。此规则仍待用户定稿，不能保证任意牌序和任意策略都能正常终局。
- 断线保留席位、取消准备，不自动判负；轮到离线者时等待本人恢复。大厅主动退出释放席位，最早入座在线成员接任房主；进行中或已结算房间退出保留席位与结果。超时60秒仅提示。全员离线30分钟回收，不补造结算。
- 没有持久化、累计积分排行榜、微信身份/分享、云部署、云数据库、真实货币或支付。
