# Gandengyan 产品需求（阶段3基线）

版本：0.3；状态更新：2026-10-23。阶段3已实现规则引擎、本地真人 + AI 会话与横屏 UI。现有 assets/scene.scene 已挂载入口，用户已确认在 Cocos Creator 3.8.5 中成功运行。微信构建、真机触摸与布局需另行验收；没有联机服务。阶段4.0仅整理Git基线、文档和验证入口，不改变玩法。

## 1. 产品目标与边界

为熟人提供微信多人联机干瞪眼娱乐体验，支持 2～8 人、1 副 54 张或 2 副 108 张牌。仅使用不可兑现的娱乐积分；不提供充值、提现、兑换、交易、现金奖池、抽成或支付接口。积分仅用于娱乐记分，不与财物挂钩。

最终包含建房、分享、入房、准备、对局、结算、再来一局及断线重连。单机模式用于本地调试与规则验证，联机模式复用同一规则源码，由服务端唯一裁决。

## 2. 阶段范围与验收

- 识别并保留现有 Cocos Creator 3.8 工程、UUID、配置和 `.meta`。
- 建立需求、规则、架构、协作规范和运行指南。
- 建立不依赖 Cocos、微信、CloudBase、浏览器或网络的 TypeScript 规则模块。
- 实现实体牌模型、完整牌堆生成和已确认配置边界校验，使用 Vitest 验证。
- 上述为已完成的初始化范围。阶段2已实现：Fisher–Yates 洗牌、注入随机源、庄家 6/其他人 5 张发牌、癞子与牌型识别、接牌、回合/补牌、首个出完胜、全局计倍和零和结算；当时不包含 UI、登录、建房、云部署或分享。
- `npm run check` 应无需启动 Creator 或连接云环境即可通过。
- 阶段3已实现：人数/牌副数/封顶主界面、选牌/出牌/过牌牌桌、按步行动的 AI、结算与重新开局。仅使用已有规则，不变更已通过测试的逻辑；仅剩王未决时显示暂停、不记分。

## 3. 用户与主流程（后续）

房主：登录 → 创建房间 → 选择规则方案和容量 → 分享至微信群 → 等待准备 → 开局。

受邀玩家：打开邀请 → 登录 → 服务端核验邀请与房间 → 加入空座 → 查看规则 → 准备。

对局：服务端发放各自手牌 → 当前玩家提交出牌/过牌意图 → 服务端校验并推进状态 → 向每位玩家发送其有权查看的投影 → 单局结束 → 服务端结算 → 再准备或离开。

重连：重新认证 → 核验席位 → 获取当前版本的公开快照和本人私有快照 → 恢复交互。不得依赖客户端缓存恢复权威牌局。

| 编号 | 需求 | 验收方向 | 阶段 |

| F01 | 房间支持 2～8 人，容量与实际人数分开 | 第九位加入失败；非成员不能操作 | 联机 |
| F02 | 选择 54/108 张牌 | 每张实体牌 cardId 唯一；双副相同花色点数可区分 | 已实现规则层 |
| F03 | 单张、对子、顺子、连对、炸弹 | 按确认后的合法/非法样例逐一验证 | 规则引擎 |

## 5. 界面范围

大厅显示建房/入房；房间页显示席位、准备状态和完整规则摘要；牌桌显示本人手牌、其他玩家余牌数、当前行动者、公共出牌及全局倍率；结算页显示原始积分、倍率、封顶处理与最终变化，公式确认后确定字段。错误提示区分网络失败、版本冲突、非法出牌和权限不足，不输出内部堆栈或秘密。

上段为最终联机目标。本地阶段主界面只有创建本地游戏和配置；没有登录/入房/分享。结算显示每人剩牌数、全局倍率、实际增减和封顶说明。真人固定第一席任庄家；AI 只用自己的牌和公开信息，所有动作提交引擎验证。支持节点复用、横屏比例适配和手牌横向滚动；具体编辑器步骤见 LOCAL_PLAY。

## 6. 非功能要求

- 公平性：服务端负责洗牌和牌局推进；客户端不决定随机种子、胜负或结算。
- 隐私：公开数据只含必要的房间和对局投影；本人手牌仅本人授权读取；底牌、牌堆顺序、随机状态仅服务端可见。
- 一致性：命令含唯一请求 ID 和期望状态版本；重试幂等，状态与结算原子提交。
- 可恢复性：断线、后台切换、消息丢失后可用快照恢复；最终延迟目标及断线宽限时间待实测确认。
- 可维护性：规则版本、配置快照与每局绑定；规则、应用、渲染和平台适配层单向依赖。
- 可观察性：记录请求 ID、状态版本、错误类别；不记录完整私有手牌、令牌或身份凭证到公开日志。
- 资源：本期仅开发依赖 TypeScript、Vitest；按需引入 SDK，避免提前加入服务端框架。

## 7. 分期与进入条件

1. 初始化：本文档和基础模块通过检查；不要求可玩场景。
2. 规则引擎：本次授权可记录合理默认值并实现；已覆盖识别、比较、状态转换和结算。剩余默认项和仅剩王分支须人工确认。
3. 单机闭环：当前提供 UI 组件与本地会话，已有 2～8 人 × 1/2 副的种子 2026 整局自动化验证。已有场景完成挂载，用户确认 Creator 运行成功；浏览器多尺寸/手机布局与微信真机验收仍需单独执行；仅剩王分支按既有规则暂停，其终局办法另定。
4. 联机闭环（规划）：先完成本地 Node.js + TypeScript + WebSocket 联机，确定认证、协议和安全边界；CloudBase仅预留适配能力，不作为本地阶段前提；实现服务端裁决、投影、幂等、重连和并发验证。
5. 微信联调：准备 AppID、开发权限、合法域名及构建环境；验证真机分享、前后台切换和多人联网。

## 8. 待决问题

规则问题统一见 [RULES.md](RULES.md)，不得以某个地区惯例作为默认。另需确认房主能否转让、是否允许中途入座/观战、房间寿命、局数、邀请有效期、昵称头像保存范围、账号注销与数据保留周期、性能目标。未确认的能力不得作为已交付功能宣传。
